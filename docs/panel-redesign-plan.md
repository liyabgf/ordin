# 面板改造工程计划

## 审查结论

用户目前要分辨 Ticket、Work、主 Session、总管、Sources、Acceptance；术语和页签先于“我要做什么”。首屏有大量系统自身状态，却没有自然语言任务入口。Agent 熟练用户需要后台、能力、授权和验收透明，但应按需展开；不应要求所有用户先理解内部模型。

目标用户：

- 新手/不懂Agent：用日常语言描述结果，不必先选Worker或理解Ticket；能确认范围、知道任务有没有真正开始、何时需要自己、结果是否被验证。
- 熟练操作者：可展开执行者、模型、权限、预算、资源/技能、验收证据与完整事件；默认隐藏诊断噪音，不能隐瞒安全降级。

## 第一版（本批）

- 主导航：首页、开始、任务、更多。旧Work/记录/设置/提示词/总管等留在更多菜单。
- 首页第一 viewport：明确“开始一项工作”和打开任务工作台；其次是需要用户处理与进行中；系统运行细节折叠。
- 开始页：友好空态、范例填充、不自动发送、自然语言 composer、每会话历史；显式Task continuation不要求用户手输ID作为日常流程。
- 任务页：全部/进行中/需要我/已结束；标题、当前状态、最近活动；详情提供进度/阻塞/结果/验收/交付动作；高级字段折叠。
- 首次配置模型与执行后端引导；配置前允许浏览，但明确闲聊可用和任务可执行的区别。
- 失败保留草稿和输入，错误说人话并给恢复动作；页面加载失败不得伪装为空。
- 尊重状态事实：Worker `ready`、Ordin acceptance、unverified、delivered 分开显示；取消请求不显示为已停止。

## 后续包

1. 新手首次体验：模型/执行环境诊断、无凭据空态、safe first-run example。
2. 任务详情时间线：计划、授权、派工、阶段、等待、验收、回报。
3. 高级任务控制：重试/补充/停止、backend/model/sandbox/budget、完整证据。
4. 来源与桥：账号映射、在线/积压/回执、原渠道回程。
5. 资产/技能/记忆：搜索与使用回执、确认/纠错/过期/来源。
6. 设置/提示词/健康：从日常主导航移到工具区，保持键盘和窄屏可达。
7. 浏览器完整验收：焦点、键盘、窄屏、空/加载/失败/权限降级、真实provider成功回合、真实用户CP。

全项目CP目标：非技术用户不学习Agent词汇即可开出任务并收到诚实结果；高级用户能还原为何执行、用了什么权限/模型/资源及验收依据。UI首版不替代真实Worker/渠道验收。
