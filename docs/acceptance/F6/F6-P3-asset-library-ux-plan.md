# F6-P3 资产库易用性与工程规划

日期：2026-11-18。状态：仅规划，功能未开工，不代表实现或验收完成。

## 1. 产品决定

资产库采用“自动资产池＋AI辅助整理”。普通任务交付后自动保存正式交付物，用户无需逐个导入、命名或选分类；系统先可靠保存，AI异步补简单说明、标签和相关性。AI失败不能阻塞交付或让资产消失。

资产库包含资料、数据、代码、Skill、工具；使用一个检索入口，但各自遵守不同启用和投射规则。自动保存不等于验收通过，不等于自动执行。记忆继续使用原有独立确认机制，不将一般文件自动变成长期事实。

默认主流程：交付→自动保存→可直接点看→看到来源和关联→选入新任务或现有任务→追踪哪个版本真正送达。复制、保存、分类由系统完成；用户只在纠错、危险启用或删除时参与。

## 3. 面板信息架构

主导航调整为：首页／开始／任务／资产／更多。资产不藏在高级设置中。资产库默认列表，按最近产生或使用排列；不要求用户理解文件路径、资产ID或配置JSON。资料、数据、代码、Skill、工具为同页类型筛选。

列表每项：名称＋类型图标、1～2行简单说明、可用状态、来源任务、更新时间、版本；名字和主要区域点击即预览。默认不显示hash、绝对路径或诊断长文本。详情可用侧栏，大屏保留列表上下文；窄屏为全屏详情并保留返回位置和搜索条件。

详情顺序：内容预览→用途说明→相关资产→来源与使用记录→版本；技术信息折叠。关系默认可读列表，不先做复杂关系图。每个相关项有原因，例如“同一任务产出”“由此版本修订”“曾被同一任务引用”；语义相似单独标为AI建议，不能伪造事实边。

## 4. 自动保存与版本合同

1. 已交付成果依据正式交付清单入池；不递归导入整个任务目录。临时文件、日志、密钥、依赖、缓存、未声明文件默认排除。纯文本回答可保存为一份报告，不要求用户先生成文件；后续实施需补其验收和内容边界。
2. 内容独立保存到受控资产存储；原任务和资产通过来源边关联。删除/清理原Ticket不能撤销资产owner或使内容失效；同时不能以此绕过跨Profile权限。
3. 保存采用持久Effects、幂等key、写临时内容→hash/完整性确认→原子落盘→记录提交；崩溃后重放不重复建资产，失败可重试并可见。备份须覆盖数据库＋内容对象，孤儿清理需有宽限期和引用检查。
4. 内容身份与资产身份分离：相同bytes可共享受控存储对象，但不同来源、用途或授权不可默默合并成同一资产；保存所有来源边。同名不同内容不覆盖，版本显式派生。
5. accepted交付可复用；unverified/rework作为待核验候选可查看，不能自动当可信资料。用户可显式作为“未验证参考”引用并保留标记，这不改成accepted。失败/取消任务不自动晋升成果，但可显式保留候选。
6. 状态分维度：保存（处理中/完成/失败）、核验（已核验/未核验）、生命周期（可用/归档/回收站）、执行启用（Skill/工具）。不要用单个status承担四种含义。内容版本不可变，说明/标签编辑不改变已引用内容；元数据版本与内容版本分开。
7. 初始上限在实现前冻结：单文件大小、任务总量、归档配额、文本提取长度、索引批量、保留期限；超限明确显示。未知格式仍可保存/下载，不执行其内容。

## 5. 简单说明与分类

确定性信息先显示：名称、MIME、大小、来源任务和交付摘要。AI整理异步执行，只读取有权限、已保存、受长度/成本限制的内容；生成短标题建议、1～2行用途说明、少量标签和可解释相关建议。用户无需启动分类任务。

AI摘要标“自动说明”，保留模型/生成时间/输入版本；用户编辑优先，不被后台刷新覆盖。AI不改原文件、不改变验收、不合并/删除资产，不启用Skill/工具。可关闭AI，分类超时或无模型时搜索、预览、保存和复用仍完整可用。先做来源关系与关键词搜索，全文/向量索引可替换且可重建，不做唯一事实源。

## 6. 新任务与活动任务复用

- 新任务草稿支持选择资产和Skill；提交时冻结assetId/revision/hash。选择器能打开内容、查看可用后端；不兼容选择要说明原因而非静默移除。执行前再验证owner、版本、生命周期、hash、能力；使用最小资产集合，不全库挂载。
- 投射到每张Ticket独立只读快照/附件目录，尽量保留真实文件格式与MIME；正文、数据、图片/二进制不能一律强制变成txt。Worker修改副本后保存为新资产版本，不能直接写全局池。
- 活动任务引用通过一条持久TaskInput与独立attachment记录原子保存；投递有幂等ID，按assignment代次围栏，禁止写到已结束/取消/换代的执行轮。
- Driver能力明确区分steer/下一轮/不支持。安全默认下一轮生效；DSH服务与Codex/Claude逐后端核实，不把DSH原生接口能力当成当前适配器能力。现有DSH服务feed只声明queued-for-next-turn，不能假称当前轮读取。
- 已排队≠已消费；选中、保存、已投射、已送达、观察到使用、使用成功为独立证据。取消/结束时未送达项目可撤回，已经消费无法假装撤回；UI说明实际状态。
- 已完成任务选择“基于这些资产新建任务”，不隐式重启Worker。

## 7. 虚拟Skill／工具池与后端投射

Ordin拥有规范资产包和版本；DSH/Codex/Claude只接收本任务需要的物化快照，各自拥有模型、认证和执行权限。虚拟池可实现为Ordin逻辑目录，但不能把写SKILL.md声称为全后端原生skill注册。

规范包：入口说明SKILL.md、references、scripts、文件清单/hash、依赖/能力声明、适用后端、来源、验证结果。工具增加可验证的输入输出schema、入口命令、版本依赖、网络/文件权限；不把指令文本误报为已注册原生工具。

每后端adapter分别说明：文件/上下文投射、原生发现（若支持）、依赖可用性、调用/结果回执、取消、清理。最低支持先做明确路径＋prompt指导读取；若原生导入不可用，界面写“任务内文件方式”，不伪造原生菜单。不得修改用户全局Skill目录或改变DSH/Codex默认配置。

任务生成Skill/脚本自动保存为候选，数据资产可自动入池但可执行能力默认不启用。验证包含结构/hash/依赖/权限审查和隔离执行；通过不等于授权。用户一次显式启用某个不可变版本及权限范围，后续兼容任务可按已保存策略自动建议/选择，无需每次重复确认；新版本或权限扩大重新确认。停用禁止新投射，对已运行副本给出真实影响，不假装撤回已执行代码。

## 9. 验收故事与门禁

| 故事 | 必须验证的事实 |
| --- | --- |
| 自动保存 | 任务交付2份报告＋1份CSV，用户不点导入即可看到3项、简短说明/来源/状态；通知可一键到资产；落盘失败不报已保存 |
| 清理不丢资产 | 在隔离state删除原任务及目录后，资产仍可读/下载且hash不变，来源显示“原任务已删除”；owner边界不扩大 |
| 新任务 | 搜索并预览，选固定revision；移除chip只改草稿；提交后真实DSH读取相同hash内容，产物记录派生关系 |
| 活动任务 | 加资料后显示下一轮生效；Worker实际读到才更新消费receipt；拔网/重启/取消/晚到响应均不串票、不重复 |
| Skill | 一个包含引用文件与无害脚本的候选包先验证再启用；真实Worker从投射路径读取/执行并给结果证据；停用阻止新任务投射 |
| AI退化 | 无模型/超时/错误分类/含敏感内容时有确定性摘要回退；用户改名不被覆盖；生成内容不执行、不晋升 |
| 生命周期 | 归档/回收站可恢复；版本冲突/已有引用/配额不足有明确反馈；不能永久删仍有活动引用内容 |
| 面板 | 1440宽与390宽、200%文字缩放、键盘焦点、空/错误/长内容；实际点击预览、来源、相关、加入、取消与重试；Console/网络无未解释异常 |

每包：最小复现、真实HTTP正负合同、真实页面行为测试、关键变异红/原字节hash恢复、隔离全量门、Chrome交互实测。数据包附旧版fixture迁移/备份恢复、崩溃重放及回滚证据；Worker包按执行端独立记录“支持/文件方式/未验证/不支持”，不能仅凭模拟测试变绿。
