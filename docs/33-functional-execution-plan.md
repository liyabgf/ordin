## 一、产品目标与完成边界

Ordin 是独立的个人协调系统：持久对话理解意图，直接回复或组织工作，按授权选择可替换的 Worker，跟踪执行，独立验收，回到原对话；数据资产、技能和可纠正记忆能被后续任务复用。DSH/Codex/Claude 是外部执行单元，不能成为 Ordin 的隐式宿主或身份源。

本轮完整交付范围包含：单人日常使用、三家 Worker 驱动契约、已声明五类来源、可恢复执行、资产/技能/记忆闭环、正式面板、安装升级备份回滚。多租户服务、原生手机设备控制、数字人格独立产品列入 F7 延伸，不暗算为 F6 已交付。

用户约束：**功能优先，全面面板 UI 改造后置**。此前用户验收只证明第三方 LLM 接入和实际对话可用，不推导真实派工、真实渠道、长期复用均已通过。

## 十一、实施组织、阻塞与证据

每次只激活一个集成批次；台账登记意图/文件所有权/禁改边界后，先写契约再实现。每包产物：合同/实现/正负测试/关键变异及恢复hash/隔离闸门退出码/验收报告/独立提交；涉及数据另附迁移和恢复证据。

复现失败后先取区分原因的证据，不重复猜修；测试环境 EPERM 与业务失败分别记录，失败日志不覆盖。临时日志不作为唯一长期证据：验收文档写命令、摘要、hash、退出码和可重新运行方式，敏感信息脱敏。

依赖缺失时记录“需要什么、最新探测时间、实际失败、能独立继续什么”；不凭历史文档断定没凭据。不可越过权限/真实数据边界。没有验证的对象保持“待验收”，不靠mock升级真实等级。
