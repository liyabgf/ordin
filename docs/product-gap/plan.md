# Ordin 产品目标缺口重评与实施改动表

## 用户定义的目标

Ordin 是长期存在的协调者与数据/工具资产管理者，不等同聊天模型，也不等同调度器：所有通道消息先归一到同一对话/身份上下文；识别闲聊或任务；闲聊直接答，任务向用户如实说明处理办法并由内部机制择 worker；资产能复用；持续记忆且越用越顺手；必要时可让 worker 在当前任务目录新建工具；Ordin 自己验收，再把结果清楚回传；用户可随时查询进度。DSH/Codex/Claude Code 是可替换的临时执行者。

本表是扫描审计，不表示下列功能已经实现或被授权本轮实施。事实来自本仓库源码与本轮主代理读取；引用 GitHub README 作为模式来源的内容仅是项目自述，不能当作其可靠性实测证明。

## 建议施工顺序（待用户批准）

1. 先锁产品事实与词汇表：Ordin coordinator、conversation/profile、worker/backend、asset/tool、memory、acceptance；明确哪些旧协议名要兼容与迁移。
2. 首个产品闭环：统一入口→闲聊/任务分流→简明说明怎么处理→按已有授权创建Ticket→验收/回传；同时接入最小可纠错的偏好/项目记忆和资产复用。三者都是基本功能，不拖到远期；没有逐项请示的默认流程。
3. 独立模型设置与面板重建：模型端点/环境密钥名/连接测试/脱敏错误；新增对话界面；浏览器实测。
4. 工具与数据资产池：先把当前SavedSkill/Artifact纳入目录和能力匹配；支持per-ticket最小投射、实际使用证据和清理。
5. Coordinator验收闭环：按任务类型组合确定性检查（文件/测试/结构/来源），worker-ready只是候选完成；验收失败可返工且不重做已完成工作。
6. 长期记忆：只从重复稳定事实形成提议，保留来源/时效/置信度；用户可审查、纠正、忘记；先单用户本地作用域。
7. 再扩worker自主造工具、多worker并行、真实多桥和发布分发；每项安全/权限独立验收。

## 扫描结论与边界

本仓库有扎实的门禁、授权、工单、效果重试、桥适配、技能/产物血缘及三后端驱动基础，但尚未实现用户描述的完整跨通道个人协调者闭环。测试基线：隔离 npm run check 退出0，43文件/812测试（/tmp/ordin-audit-baseline.log）；当前运行服务/真实渠道/真实模型未验证。实际部署要等新产品闭环完成后再次启动验收。本报告完成后不实施表中项目，等待用户的下一步授权。

## 如何减少被更强模型替代的风险

不能保证任何软件永不淘汰。可以明确把长期价值放在用户关系、可信记录、资产所有权、权限、跨通道连续性、任务验收与执行接入上；把判断模型、规划模型和执行者都做成可替换组件。能力越强的模型应该减少规则补丁和执行步骤，而不是迫使用户迁出全部数据与记忆。路由策略可简化为模型直接建议，但授权、事实持久化和验收证据不跟某模型绑定。

## 工作质量与验收的责任边界

Ordin不承诺worker一定把活做好，也不为不可检验领域伪造质量保证。它负责在派工前明确交付要求，收回后检查可检查的事实：文件是否存在和可打开、测试是否实际通过、引用是否可追溯、任务要求是否覆盖、失败与未验项是否清楚。主观判断可借另一模型评审，但其结论仍是证据之一；无法独立验证时告诉用户“未验证”，不能说“已验收”。
## 必备内核、可借资产与临时能力的边界

| Ordin必须自带 | 从虚拟资产池按需借出 | 可让worker在当前任务临时新建 |
| --- | --- | --- |
| 身份/授权、收件去重、对话分流、任务记录、能力目录、派工/取消、检查验收、回程、记忆纠错、资产生命周期 | 有来源/版本的技能包、模板、脚本、资料集、项目成果和受授权数据连接引用 | 数据格式转换脚本、研究采集器、任务测试器、一次性适配器、临时报表生成器 |

凭据、权限范围和验收规则不能由worker临时伪造；临时工具默认不直接进入永久技能池。普通可逆工具的创建和复用应自动完成、留账可撤销，不给用户制造日常审批队列；外部高影响行为遵循用户既定授权。推广到长期资产以自动检查/验证状态为门槛，人工介入只针对必须由用户决定的范围。

## 用五条真实使用故事验收

1. 飞书闲聊直接回复、不建任务；Telegram提出工作则解释目标和验收办法；同一用户从网页追问时能定位相同项目，不靠猜。跨通道绑定必须由用户确认，不以同名自动合并。
2. 新任务自动发现上次已验收的数据与适用技能，向Codex临时投射选定版本；换Claude执行后仍可用同一资产，不迁走个人状态或权限。
3. 缺一个转换脚本，Ordin让worker在任务目录创建并测试；使用后记录效果，有重复价值再自动进入候选技能并验证，不污染永久环境。
4. worker报ready但产物缺页，Ordin验收不通过、要求补齐；报告用户实际完成与未验证项。worker出错不被Ordin包装成成功。
5. 用户纠正“以后别每步都通知我”，跨渠道下次仍遵循；能查看来源并撤回偏好。后续相似任务更少重复查找/建工具，在不降低验收通过率的前提下减少用户干预。

“越用越好用”用指标评估：相同类任务的澄清/人工干预次数、重复工具创建次数、有效复用率、错误记忆率、验收后返工率与耗时/成本；不能只看memory条数、技能数或模型自报成功率。
