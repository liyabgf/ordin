# 总管资产目录写入：产品合同与阶段 5b 评审

状态（2026-11-19）：阶段 5 设计已交付；阶段 5b 评审决议为暂不开放。本文所述批准状态、API 和回执为将来合同，当前版本没有这些入口。

## 现在可用的路径

导入、编辑元数据和归档留在本机操作者面板。`http.ts` 的同源请求守卫是传输边界；业务检查由 `AssetCatalog` 执行。当前 `PATCH` 合同为兼容允许省略 `expectedRevision`，提供时才检查冲突。现有 revision 预期值防并发误覆盖；它不是对话授权。default Profile 和本机管理请求均不建立经认证的审批主体。总管可以读资产目录或按现有合同给任务附加固定资产引用，不能改目录。

## 将来单条变更的确认流程

每次提案只绑定一个确切资产，允许编辑名称（`name`）、描述（`description`）、标签（`tags`），或将资产归档（`archived: true`）。导入、删除、覆盖正文、批量操作、任意脚本、恢复已归档对象不进入该路径。

| 状态 | 操作者可见行为 | 服务端责任 |
|---|---|---|
| `pending` | 在管理面板的待确认列表看到资产标题和 ID、当前版本、逐字段旧值与新值、归档影响及失效时间；可打开、确认或取消。 | 按受信任会话与来源权限生成不可修改的提案，绑定审批范围、确切对象、变更内容、版本、内容哈希和失效时间。模型只能提交候选，不能替操作者确认。 |
| `applied` | 确认可见最终结果及新版本；再次查询返回原回执。 | 由独立的操作者审批动作触发。一次事务内复核主体、对象和来源权限，校验提案状态和版本/哈希，写入资产、消耗提案并保存回执。重复确认不再次写入。 |
| `cancelled` / `expired` | 显示已取消或已过期，旧卡片不能再确认。 | 取消和审批都必须校验同一审批边界，且仅允许从 `pending` 转移；提交时重新检查服务端时钟。过期、重启和清理必须保留可解释状态，不自动执行。 |
| `rejected` | 因版本冲突、权限变化、对象消失或状态改变而被拒绝。若仍要修改，刷新后重新提出并审批。 | 写入前重新授权并核对对象当前状态；报告明确原因，不自动替换目标、升级版本或重试。 |

API 按创建提案、读取状态、批准、取消分离，批准请求只引用服务端提案，不能携带任何可覆盖目标、版本或变更的字段。不采用聊天里的“确认”或模型文本作为批准信号。凭同一事务的持久回执处理响应丢失；无法确认提交结果时先查询，不盲目重放。是否需要额外签发票据取决于最终批准通道的威胁模型。

面向总管的结果仅包含提案 ID、目标 ID、操作类别、状态、版本、时间和安全原因码。内部审计再记录经过验证的主体和入口、请求 ID、授权与版本校验结果；不记录秘密、磁盘路径、正文或变更的完整自由文本。

## 阶段 5b 评审裁决

当前同源标记不能把异步批准绑定给可复核的操作者；default Profile 也不能证明操作者身份。现有通用 `PATCH` 没有上表的提案状态、绑定、过期或原子回执，直接复用会绕过发布门槛。因此本版不投影任何总管资产目录写工具，也不把现有 UI 写能力包装成对话审批。

重新评审核对三件事：先明确受信任本机审批通道及其主体绑定；再落地领域层对象/来源权限、强制版本/哈希和原子审批事务；最后在隔离 HTTP 和浏览器验证确认、取消、过期、跨对象/跨主体拒绝、版本竞争、重复提交、重启、回执及审计脱敏。多用户仍另需认证和对象级 ACL。通过前处于「仅有设计」。
