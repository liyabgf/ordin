## 需要你决策的点

1. **M1 是否包含最小记忆与资产复用**——我建议包含（它们是“越用越好用”的最小闭环），代价是批次一多约 1-2 周。
2. **协议名是否随界面一起改**——ordin_* 工具名、ORDIN_* 环境变量、锁文件名。我建议 M2 一并迁移并提供兼容窗口；若你要求 M1 就零旧词，批次一会显著变大。
3. **旧面板处置**——我建议重建新面板、旧单文件归档不再维护，而不是在旧结构上继续修补。
4. **真实后端验收时机**——需要你配置 DSH key / Codex 登录 / Claude 登录；可以与其他工作并行，你配好一家就验一家。
5. **数据资产管理的 LLM 边界**——我建议 LLM 只做检索/摘要/标注/去重建议；写入与删除走受约束资产 API，不做自由文件操作。

## 风险

- schema v7→v8 迁移触碰用户数据：必须备份/回滚演练后才在你的真实目录执行。
- 单文件面板 5100 行重建是最大工作量项；已列为独立 WP 并允许新旧并存过渡。
- 三家 CLI 周级版本漂移：契约测试+pin 版本是长期成本，不是一次性工作。
- WP-2.5 分流评测依赖真实会话语料；先用构造场景，你的真实使用后再校准。
